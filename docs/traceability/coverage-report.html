4 条不符，指向同一个产品缺陷
GET /admin/dict-items、/admin/dict-items/by-code、 /admin/files/view（管理端与 C 端各一）在缺少必填参数时返回 HTTP 500 + code 50000，而不是 400 + BAD_REQUEST。
对比 POST /admin/auth/login 缺 username 能正确返回 400 + 40000， 说明不是全局约定，是这 4 个接口漏了参数校验。同时这 4 条用例本身是「正向」用例， 参数列把必填项也当成可选项省略了——用例和产品各有一个问题。
顺带确认了全系统的响应约定
业务异常走 HTTP 200 + body 数值码（源码 GlobalExceptionHandler 没有 @ResponseStatus）： 评价回复缺内容 200/40000，回复不存在的评价 200/40400，回复超 500 字 200/40000； 只有安全层拒绝才返回真实 4xx（未带 Token → 401/40100）。 这决定了后续所有负向用例的预期该怎么写。
