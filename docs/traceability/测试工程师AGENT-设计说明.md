# 测试工程师 AGENT · 设计说明

> 目标：当需求**暂时没有测试用例**时，由一位「资深测试工程师 AGENT」接管：
> 读取产品文档 AGENT 还原出的 PRD + 追溯链上的真实代码证据，
> 按**专业测试方法论**生成详细、专业、全面、可直接执行的测试用例。
> 核心原则：**每条用例都能指认它的设计方法与代码证据，不凭空编造场景。**

---

## 1. 角色画像

AGENT 的角色设定是一位 15 年电商测开经验的资深测试工程师：

- 熟悉电商核心域（订单五态、售后三态、库存不变式、支付沙箱）；
- 依据需求优先级与风险定用例优先级，P0 需求绝不漏正向主流程与安全用例；
- 坚持「用例三要素」：前置条件可构造、步骤可执行、预期结果可断言
  （HTTP 状态码 / 业务码 / 数据库校验点，三者至少占其二）；
- 输出前自检：去重、覆盖矩阵核对、与既有用例不冲突。

## 2. 方法论体系（7 类设计方法）

| # | 设计方法 | 适用对象 | 用例类型标签 |
|---|---|---|---|
| 1 | 场景法 | 功能点、验收标准 | 正向 |
| 2 | 边界值分析 | 数值/长度/数量/分页参数 | 边界 |
| 3 | 等价类划分（无效类） | 接口参数类型、枚举取值 | 异常 |
| 4 | 状态迁移法 | PRD 状态机（订单五态/售后三态） | 状态流转 |
| 5 | 错误推测法 | 幂等键、乐观锁、唯一约束、并发 | 并发幂等 |
| 6 | 安全测试 | 鉴权（trace_apis.auth_requirement 真实值）、越权、脱敏 | 安全 |
| 7 | 数据一致性校验 | 下单快照、库存不变式、金额合计 | 数据一致性 |

每条用例标注 `designMethod`（设计方法）与 `relatedApi`（被测接口），
评审时可直接回答「这条用例为什么存在、测的是哪个接口」。

## 3. 生成流水线（6 个 Stage）

```
Stage 1  输入解析    单需求（requirementId）或全量批量（无用例的需求）
   ↓
Stage 2  证据采集    复用产品文档 AGENT 的追溯链 BFS + 契约补全：
                    接口契约（method/path/参数/必填/类型/鉴权）
                    数据模型（表/字段/类型/主键）
                    状态机（flows）、业务规则、负面清单 NEG-Sxx
   ↓
Stage 3  测试分析    三张分析表：
                    ① 功能点→场景表     ② 接口→参数矩阵表     ③ 状态机→迁移表
   ↓
Stage 4  用例设计    按 7 类设计方法逐表生成；每条含设计方法、优先级、
                    可断言预期（状态码/业务码/DB 校验点）
   ↓
Stage 5  质量自检    同需求内按标题去重；优先级定级复核；
                    覆盖矩阵核对（每个功能点≥1 正向，每个 NEG≥1 用例）
   ↓
Stage 6  落库        写入 testCases（documents 存储），status=待评审，
                    source=测试工程师AGENT，与人工用例同构可评审
```

## 4. 用例结构与规范

与平台既有 testCases 结构完全同构（可进入评审流、Excel 导入导出），扩展四个专业字段：

| 字段 | 说明 |
|---|---|
| `designMethod` | 设计方法（等价类/边界值/状态迁移法…） |
| `relatedApi` | 被测接口（METHOD /path，来自 trace_apis 真实扫描） |
| `testData` | 构造说明（测试数据准备方式） |
| `dbCheck` | 数据库校验点（一致性类用例的断言落点） |

**预期结果规范**：正向用例必须含业务码断言；异常用例必须含 HTTP 状态码
或业务错误断言，并明确「不应产生部分写入」；一致性用例必须给出表级校验 SQL 语义。

**优先级定级**：

- P0：主流程成功、必填校验、状态机非法迁移、鉴权/越权、负面清单 NEG；
- P1：边界值、类型非法、并发幂等、数据一致性；
- P2：展示类、提示文案类。

## 5. 与双引擎的关系

| 引擎 | 定位 |
|---|---|
| 外部 AI API | 通用大模型生成，灵活但需 API Key |
| 系统内部逻辑 | 轻量模板引擎（case_engine_local），快速兜底 |
| **测试工程师 AGENT** | **方法论驱动的专业引擎**：读 PRD+接口契约+状态机建模，输出量与深度对齐人工资深水平 |

三类引擎输出同构，走同一条评审流水线；AGENT 生成的用例额外携带
designMethod / relatedApi / dbCheck，评审页面可识别来源。

## 6. API

| 接口 | 说明 |
|---|---|
| `POST /testcases/agent/generate` | body: `{requirementId?, dryRun?, overwrite?}`；单需求或全量批量生成 |
| `GET /testcases/agent/preview/{requirementId}` | dry-run 预览（不落库） |

前端入口：需求详情页「关联测试用例」区块——当需求无用例时，
主按钮切换为「资深测试工程师 AGENT 生成用例」。
