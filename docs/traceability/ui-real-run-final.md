## 八、结论与局限

1. **系统可以真实执行 UI 自动化**：120 条用例由平台（CLI 与 HTTP 接口两条入口）驱动浏览器完成，456 个业务断言全部通过，22 笔订单真实落库。
2. **v1 的「通过」是假通过**：未选规格导致加购被拦截、同名元素被遮罩挡住、提交订单的二次确认未处理——这些都不会抛异常，只看「步骤没报错」会把失败判成通过。断言是唯一可信的判据。
3. **UI 层只覆盖用户可见结果**：诸如「库存 locked 增加」「金额一致性」属于 DB/API 断言，本报告不把它们算作 UI 通过；74 条业务规则/权限类用例仍保留为 design_check。
4. **PO 是按标题关键词匹配的通用路径**：同一条 PO 会被多条用例复用，覆盖的是「路径级」，不是每条用例独有的异常分支；异常分支需要专门的 PO 与测试数据。
5. **写操作配额**：下单/支付会真实修改库存与订单，批量执行默认限量（本次跑到 22 条），避免耗尽演示库存。
