# 设计审计与专业化方向

> 审计对象：`design/baseline/screens/` 下 44 张 1440×900 现状截图。  
> 审计目的：不是否定现有实现，而是找出“为什么看起来像内部工具，而不是专业产品”的具体原因，并给出 Figma AI 可执行的方向。

## 1. 结论

当前系统**功能骨架完整、信息架构清楚**，但视觉层仍停留在“可用的后台模板”：

- 页面之间靠同一套白卡片 + 表格拼接，缺少品牌识别和页面节奏。
- 字号偏小、层级偏弱，用户需要靠颜色和边框分辨信息。
- 重要页面（工作台、需求详情、AI 对话）没有把“下一步该做什么”放在视觉中心。
- 空状态、加载、错误、权限不足几乎没有设计。
- 只在 1280px 以上可用，没有响应式策略。

如果直接进入开发，会继续堆功能、继续变得难维护。建议先用 Figma 完成 **3 个基准页 + 6 个核心组件** 的专业化重绘，再反推代码。

### 现状评分（10 分制）

| 维度 | 分数 | 说明 |
|---|---:|---|
| 品牌识别 | 4 | 只有顶栏和一张渐变 banner 有辨识度 |
| 信息层级 | 5 | 标题/正文/辅助文字差距小，表格密度高 |
| 布局与留白 | 6 | 结构规整，但大量空白与拥挤并存 |
| 组件一致性 | 6 | 基础组件统一，但状态和尺寸体系不完整 |
| 状态设计 | 3 | 空/加载/错误/权限状态基本缺失 |
| 可访问性 | 4 | 11–12px 字号、部分对比度不足、焦点样式不完整 |
| 响应式 | 2 | 未定义 1280 以下行为 |
| 专业感 | 5 | 像“能跑的内部系统”，不像“可交付的产品” |

## 2. 关键问题与改法

### 2.1 字号太小，层级靠“加粗 + 颜色”硬撑

**证据**：全局正文/表格 12px，辅助文字 11px，页面标题只有 16px（见 S04、S09、S23）。在 1440px 宽度下，表格内容显得密而轻，长时间阅读疲劳。

**改法**：
- 正文 14px，表格 13px，标签 12px，页面标题 28px，区块标题 16–20px。
- 指标数字 28–36px，使用 tabular-nums。
- 建立 5 级文字层级：Display / Page title / Section / Body / Caption。

### 2.2 顶栏与侧栏承载过多入口，当前层级不清晰

**证据**：顶栏同时有 7 个全局入口 + 项目切换 + 管理后台 + 通知 + 用户（S02）。项目层侧栏 9 个一级菜单（S04）。用户很难判断“我现在在全局还是项目内”。

**改法**：
- 顶栏收敛为：Logo / 工作台 / 项目空间 / 资产（技能 + MCP）/ 团队 / 设置。
- 项目切换器作为“当前上下文”，放在 Logo 右侧或面包屑行，不与全局导航并列。
- 管理后台收进头像菜单，仅管理员可见。
- 侧栏按“核心流程 / 自动化 / AI 与知识 / 交付”分组，组间加 8px 分隔和组标题。

### 2.3 页面骨架同质化，缺少页面类型差异

**证据**：工作台、需求列表、用例列表、API 管理、知识库文档都是“标题 + Tab + 白卡片 + 表格”（S02、S04、S06、S09、S23）。详情页和生成页也只是左右分栏。

**改法**：明确 7 种页面模板（见 `DESIGN.md` 第 7 节），不同类型使用不同的布局节奏：
- 工作台：指标 + 图表 + 待办，不是表格。
- 列表：筛选 + 表格 + 分页。
- 详情：摘要栏 + Tab 工作区。
- 生成：配置 + 预览 + 底部动作。
- 编排：三栏画布。
- 对话：会话 + 消息 + 引用。
- 报告：摘要 + 分布 + 明细。

### 2.4 空状态、加载、错误、权限状态缺失

**证据**：S09 接口管理空表只显示“暂无数据”；S05 需求详情右侧显示“点击生成原型图开始”；多处页面加载时是整页“加载中…”。没有骨架屏、没有下一步动作、没有错误恢复。

**改法**：
- 空状态 = 图标/轻插画 + 一句解释 + 一个主操作 + 一个次要帮助链接。
- 加载 = 表格骨架 5–8 行 / 卡片骨架；不要整页 spinner。
- 错误 = 原因 + 重试 + 联系管理员；保留用户已填内容。
- 权限 = 说明缺什么权限 + 找谁开通 + 返回上一页。

### 2.5 状态色使用过度，标签像“彩虹”

**证据**：需求列表同时出现 P0 红、待解析黄、已解析绿、模块蓝、独立需求灰；表格里颜色块密度高（S04）。API 方法、状态、优先级都使用相近的浅色底。

**改法**：
- 只保留 5 种语义色；同一行最多 2 个彩色标签，其余用中性色。
- 优先级用“文字 + 左侧 2px 色条”而不是整块底色。
- 状态用“圆点 + 文案”，减少色块面积。
- 主色只给“当前选中/主操作”，不要给普通标签。

### 2.6 表格缺少“阅读路径”

**证据**：S06 用例列表、S23 文档列表的列宽平均、操作列按钮多、行高 40px；用户视线从左到右要跨很大距离。S04 需求树的子需求标题被截断，操作列与标题竞争。

**改法**：
- 行高 48px；表头 40px；首列固定；操作列固定右侧，默认只显示一个“更多”菜单。
- 数字右对齐，状态列固定宽度，长文本两行截断 + tooltip。
- 批量选择、排序、列配置作为表格标准能力。
- 20 条/页起步，超过 20 条分页或虚拟滚动。

### 2.7 详情页左右比例失衡

**证据**：S05 需求详情左侧 1/4 信息卡，右侧 3/4 工作区，但工作区在未生成时是一大片空白；左侧信息卡字号 12px，字段拥挤。

**改法**：
- 左侧 320px 摘要栏：标题、状态、优先级、负责人、版本、更新时间、主操作。
- 右侧工作区用 Tab + 空状态引导；默认展示“下一步建议”，而不是空白。
- 信息字段用“label 12px + value 14px”，不要全部 12px。
- 把“生成原型图 / 生成用例 / 拆分需求”做成明确的主/次操作层级。

### 2.8 浮层遮挡内容

**证据**：右下角任务浮层在 S04、S06、S09 等页面遮挡表格底部操作列；通知中心也是浮层。当前已改为默认收起，但仍需安全区。

**改法**：
- 默认收起为 40px 小条；有新任务时展开。
- 内容区底部预留 64px；窄屏改为底部抽屉。
- 通知中心使用右侧 Drawer，不与任务浮层同时出现。

### 2.9 图表与指标缺少口径

**证据**：工作台“本周生成用例 486 ↑18%”“测试通过率 92.4% ↑2.1%”“本月 Token 12.8M ↓24%”没有说明对比口径；Token 趋势图只有柱形和星期，没有单位、图例、空状态。

**改法**：
- 每个指标卡加“对比口径”（较上周/较上月）和更新时间。
- 图表加单位、图例、hover tooltip、空状态、加载状态。
- 通过率用目标线/阈值，而不是单独一个数字。

### 2.10 响应式与可访问性欠账

**证据**：固定 208px 侧栏 + 多列 grid；1280 以下没有断点；11px 文字、20px 展开按钮、部分浅色文字对比度不足。

**改法**：
- 定义 1440 / 1280 / 1024 / 768 / 390 五档。
- 可点击目标 ≥ 32px（桌面）/ 44px（移动）。
- 焦点环、ARIA、键盘顺序纳入验收。
- 表格在窄屏转卡片列表。

## 3. 推荐视觉方向：Precision Workspace

### 概念

> 一间安静的测试控制室：深色导航像仪表台，内容区像精密仪器的读数面板；颜色只用来标记状态和动作，不用来装饰。

### 视觉锚点

1. **深石墨顶栏** `#0B1220` + 钴蓝主色 `#2D5BFF` + 青色 AI 强调 `#0891B2`。
2. **大标题 + 大数字**：页面标题 28px，指标 28–36px；表格 13px 保持密度。
3. **卡片轻、边框细、阴影几乎不可见**；靠留白和分隔线建立层级。
4. **状态点 + 文案**，减少整块浅色标签。
5. **图表用细线、少网格、直接标注**；不要 3D、不要渐变填充。
6. **动效克制**：150–200ms，只用于展开、抽屉、任务进度。

### 可选的第二方向（用于 Figma 探索）

- **Soft Industrial**：暖灰画布 `#F4F1EC` + 墨黑 `#1C1917` + 柠檬绿强调 `#65A30D`；更偏“设计工作室”，适合品牌展示，但数据密集页面要谨慎。
- **Deep Tech**：深色全站 + 青色霓虹；视觉冲击强，但长时间使用疲劳，不建议作为默认主题。

建议只把 Precision Workspace 作为主方案，第二方向只做 1–2 帧对比，不要分散精力。

## 4. Figma 重绘优先级

### P0：先做这 3 页，批准后再扩展

1. **工作台**（S02）：决定品牌第一印象、指标卡、图表、待办、浮层规则。
2. **需求列表**（S04）：决定表格、树、筛选、状态标签、操作列。
3. **需求详情**（S05）：决定摘要栏 + Tab 工作区 + 空状态 + 主操作层级。

### P1：核心业务闭环

4. 用例列表（S06）
5. AI 生成用例（S07）
6. 用例评审（S08）
7. AI 对话（S20）
8. API 管理（S09）
9. 知识库文档（S23）

### P2：其余页面

按 `design/page-inventory.md` 的顺序逐页套用模板；不要一页一页从零画。

## 5. 不能改变的东西

- 路由、菜单层级、权限模型、数据字段、接口协议。
- 现有业务动作：上传/拆分/确认、生成用例、评审通过、导入导出、API 执行、知识库召回。
- 现有组件的交互语义（按钮是按钮、表格行可点等）。
- 不在 Figma 里发明新功能；只做视觉、布局、状态和文案优化。

## 6. Figma AI 探索检查清单

- [ ] 是否使用了 `tokens.proposed.json` 的颜色/字号/间距？
- [ ] 页面标题、区块标题、正文、辅助文字是否有 4 级以上层级？
- [ ] 表格是否有空/加载/错误/选中/操作菜单状态？
- [ ] 主操作是否唯一？次要操作是否降级？
- [ ] 1280 / 1024 / 390 是否有明确降级？
- [ ] 焦点环、对比度、点击目标是否达标？
- [ ] 是否去掉了不必要的渐变、阴影、彩色标签？
- [ ] 是否保持现有业务动作不变？

| 主要页面文字 ≥ 13px | 是 |
